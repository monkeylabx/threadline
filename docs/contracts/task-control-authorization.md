# Slice A Task control authorization

Status: proposed G2 contract for [#354](https://github.com/monkeylabx/threadline/issues/354), under [#350](https://github.com/monkeylabx/threadline/issues/350). Inputs: integrated [Core Task profile](./slice-a-task-control.md), [Runtime control](./runtime-control-delivery.md) and [dev authored fields](./slice-a-authored-fields.md). Documentation/reference decisions only; no executable Task authorization, current-fact adapter, schema or production admission is added.

## 1. Responsibility and interface

The Task authorization module decides whether one independently authenticated principal may perform one registered Task control action against one currently resolved resource. It returns a one-use decision, never a Grant, effective-permission cache, business transition or persistence effect. Transport authentication, fact resolution, business transitions and protected effect admission remain separate adapters. Callers and tests use the same planned `AuthorizeTaskControl(principal, request, facts)` interface. The trusted adapter selects action, exact resource and purpose (`operation` or `own_receipt_read`); RPC callers cannot choose a weaker purpose. Command identity fields are equality assertions, not authority. Its pure `CurrentApprovalEligibility(approval_binding, facts)` operation computes the eligible identity intersection for decisions and #365's protected-use check; that set alone authorizes no caller, effect or write.

`facts` is a complete, versioned, request/transaction-bound snapshot from trusted Core adapters. It includes current identity liveness, Organization/Member, parent Channel Membership/ACL decisions, immutable Task participants/manifest, Task-control policy, assigned Runtime/Agent/Device, initiating Human delegation and the relevant Run/Approval/Grant/action facts. An unavailable/malformed required fact is not an empty set or a permissive default. Fixture booleans and renderer claims are synthetic inputs, not adapters. Cancelled/deadline-expired calls return no allow.

Output binds decision/reason, principal, action/purpose, tenant/resource/parent, current policy/ACL/membership and aggregate revisions. Denials expose only currently disclosable C2 identifiers/versions. No raw credential, authored content, prompt, prepared arguments, content commitment, physical path or reusable Grant bytes. Even a successful decision cannot be reused after its fact/transaction scope ends. The profile and fixtures can be reverted independently before implementation; persisted/wire successors require separate compatibility/rollback review. Existing domain terms in [CONTEXT.md](../../CONTEXT.md) retain their meanings.

The existing [evaluator](../../services/core/internal/authorization/evaluator.go) and [current resolver](../../services/core/internal/authorization/current/current.go) recognize only Space/Channel actions/resources. In particular, an existing Organization Owner + Channel Owner branch returns a broad role allow after registry checks. **Do not add these strings to that registry and inherit its generic allow.** Use a separate closed Task-action registry/matrix and explicit parent-check port; continue invoking the old evaluator only with its unchanged Channel actions. No Task action is added to the old Channel ACL entry vocabulary in this task.

## 2. Closed action and parent-check matrix

Resource lookup always derives Tenant from the verified principal. Resolve `Approval → Run → Task → Channel` through tenant-composite keys; a supplied parent, Agent, Runtime or Device ID must equal the resolved binding. There is no Task visibility independent of the parent. A public Channel's discovery permission is insufficient. Slice A supports Channel parents only; DM, editing/participant changes, transfers, Artifact operations and unknown actions remain unsupported after method authentication.

| Action | Exact resource / operation | Parent decision(s) | Eligible principal and additional ceiling |
| --- | --- | --- | --- |
| `task.create` | Channel / CreateTask | `channel.read` AND `channel.publish` | Human; one readable retained trigger, trusted target/assignment and derived participant set. |
| `task.read` | Task / GetTask | `channel.read` | Human Channel reader; no Task participant requirement. Full authored view also requires current source-history entitlement. |
| `run.start` | Task / StartRun, including explicit fresh retry | `channel.read` AND `channel.publish` | Human stored Task `OWNER`; current target, initiating delegation/capability scope and business retry barriers. |
| `run.read` | Run or Task-scoped Run list/stream | `channel.read` | Human Channel reader; or authenticated assigned Runtime through #348's metadata-only internal port. |
| `run.control` | Run / CancelRun | `channel.read` | Human stored `OWNER`, `OBSERVER` or `APPROVER`, explicitly enabled for control by current policy. No execution authority. |
| `approval.read` | Approval or Task-scoped own queue | `channel.read` | Human Channel reader with current source-history entitlement for authored fields. Queue selection is only the caller's current eligible queue for this Task; it does not widen visibility. |
| `approval.request` | Run / RequestApproval | `channel.read` for assigned Agent and operator | Authenticated current execution Runtime for the stored Agent `ASSIGNEE`; current Run execution authority/delegation and exact bounded action. |
| `approval.decide` | Approval / approve OR reject | `channel.read` | Human in the stored eligible snapshot AND current role/policy/resource intersection (§5). `ONCE` only. |
| `approval.revoke` | Approval / RevokeApproval | `channel.read` | Same current Human eligibility intersection; revocation narrows authority, never issues it. |
| `run.report` | Run / RUN_STARTED or normal CompleteRun | `channel.read` for assigned Agent and operator | Authenticated current execution Runtime, exact Agent/Device/owner generation, live lease/fence and current execution authority. |

Human parent decisions bind that Human's current principal. Runtime decisions separately bind the assigned Agent's standing application permission, the authenticated operator Human's current read permission and the exact delegation; never synthesize a Human Session from a Runtime credential. Runtime's `run.read` returns only its assigned Run's authorized C2 control projection. It cannot use Human Task/Approval read RPCs, obtain authored fields or enumerate other Runs. A bare Agent credential or Gateway service identity is insufficient for this Runtime path. Grant metadata and application membership never imply Channel/Epoch keys.

Creating/starting/requesting work, approving new authority and normal execution/reporting require an active parent Channel. Archived Channels remain readable under the unchanged parent rules; authorized CancelRun, rejection and revocation can still narrow authority there. Pending-deletion parents deny ordinary Task access. An archived/deleted/revoked parent never prevents #348's independently authenticated local stop/restricted cleanup. Those ports are separate from normal `run.report`; they cannot grant execution or general reads.

Initial Task-specific role ceilings are explicit: reads permit all five known Organization Roles and all four current Channel Roles when the parent allows. Creating, starting, approving, and Runtime execution require non-Guest Organization and Channel Roles for every participating authority (initiator, approver, Agent/operator as applicable). This is an additional Task ceiling; existing Guest IM publish/read behavior is unchanged. A Guest who is already a stored participant may perform content-free CancelRun when current control policy allows. Organization/Channel Owner, Admin or Security Admin has no Task-role, membership, history, approval or Runtime-owner bypass.

## 3. Trusted Task policy and participants

The initial policy schema is `task-control-auth/1`, with a current nonempty policy ID/revision and exact deployment/tenant/Channel scope, resolved from operator/Core-owned configuration. Its action rules explicitly enable registered actions. Read rules name `channel_readers` (and `assigned_runtime_metadata` only for `run.read`); mutation rules list permitted Task roles within §2's ceilings. An omitted action/audience/role is deny. Actor-specific constraints can only narrow. Wildcard actions/roles, unknown policy versions and caller-supplied policy documents cannot enable an operation.

Policy also names permitted Agent assignments, exact target Runtime–generation/operator–Device bindings, current capability/resource delegation ceilings, configured Human approvers/observers, and `allow_owner_self_approval` (default false). These facts are resolved and bound independently; online/capacity advertisements do not supply them. An offline but currently permitted target can queue; unavailable target authority cannot. Policy revision changes force a new current evaluation, not reuse of an old allow. An unrelated compatible revision may pass all current checks; version equality with creation is not itself authorization.

Core derives one creator `OWNER`, one configured Agent `ASSIGNEE`, and configured permitted Humans as `APPROVER` or `OBSERVER`, at most 16 distinct Actor type/ID pairs. Each Actor has exactly one role. The creator remains only `OWNER` even if explicitly eligible for dev self-approval; no duplicate `APPROVER` row. An Agent cannot become a Human approver, and a Human Device owner is not the Agent's execution owner. Unsupported Human-assignee/extra-owner roles are refused in this subset. Unknown/duplicate caller roles are invalid; inconsistent persisted participants are unavailable facts, not an inferred repair.

An empty request participant list asks Core to derive the set; it does not create an empty/private Task. A nonempty list must exactly match the derived identity/role set (order is not authority); caller timestamps are unsupported. This clarifies #347's trusted-set requirement without allowing caller-selected roles. #355 must still include the caller's semantic input in retry identity, so switching between omitted and explicit participants under a committed key is not an invisible rewrite. No participant changes or additions are supported after creation.

The selected target must match an independently verified Runtime enrollment, active authorized Device and operator Member, enabled assigned Agent and an explicit current delegation for that Task/Run/resource scope. Request IDs, Task ownership, matching Device strings or a valid signature alone cannot establish the binding. The initiating Human must still have current parent/resource authority sufficient for every delegated operation; if a delegation explicitly binds a Session/Device, its liveness is also required. Runtime authentication uses its own audience/generation/expiry, not an assumed live initiating login. None of these checks grants user-file access or creates a Workspace.

## 4. Current facts, source access and refusal ordering

| Fact family | Required trusted binding / observation |
| --- | --- |
| Principal | Human Session/Device or #348 Runtime credential/audience, current expiry/revocation, tenant and exact Actor/operator/Device identity. Active credentials do not imply active membership. |
| Parent | Active Organization/Member; known Organization/Channel Roles; current Channel Membership interval; same-principal current read/publish decisions including explicit ACL version, deny-over-allow and default effect. A departed interval is never current. |
| Source | Trigger's exact tenant/Channel/event identity, retention and current interval read entitlement, or explicit still-current History Sharing for that exact retained source. Joining/rejoining or knowing an event ID cannot restore older history. |
| Task | Immutable parent/creator/participants/manifest identity/version and current Task policy; no policy row from another Channel/Actor. Child Task/Run/Approval bindings agree. |
| Runtime / delegation | Current enrollment/generation/operator/Device/Agent assignment; initiator and Agent standing limits; scoped unexpired/unrevoked execution Grant and exact owner lease/fence. Heartbeats/cached snapshots are insufficient. |
| Approval / action | Eligible Human snapshot, current eligibility/policy/resource authority, immutable action identity/version/binding/capability/scope, current decision/expiry, consume/cancel/barrier state and issued-Grant relation. |

Evaluate in this order: authenticate/current principal; validate action/purpose and bounded request shape; tenant-scoped lookup; validate minimal principal/parent fact bindings and current read disclosure; validate remaining required facts and parent publish/ACL/role checks; Task policy/role/source/target/delegation checks; operation-specific approval/owner checks; then the business module checks state/races and commits. A later allow never revives an earlier deny. Request conflicts and operation preconditions cannot disclose a foreign/unauthorized object. A resolver returning foreign/stale/mismatched evidence is a fact-source failure, not permission to evaluate a narrower incomplete bundle.

Pure Run/C2 control metadata may remain visible to a current Channel reader after loss of original-trigger history access. Full Task/Approval views include C3 authored fields, including plaintext dev wrappers: for this one-trigger profile they additionally require current entitlement to that exact retained trigger. Current membership or knowing a Task ID cannot bypass that guard. GetTask/GetApproval/ListApprovals return a complete authorized object/page or a clear history/retention error, never absent required fields or an empty-text substitute. Metadata-only views exist only on an explicitly declared interface (Run reads/#348 snapshots); do not invent silent redaction in an old response.

Creation, every new Run, full authored-view read and locald's actual resolution independently check the exact source; no old membership/History Sharing snapshot is authority. Task/Approval authored reads also require #353's negotiated profile and real cryptographic admission where applicable. History Sharing of the source does not itself distribute Task/Epoch keys. Neither metadata read nor Task participation authorizes content beyond the manifest; future multi-source/private work needs its own reviewed visibility contract. This narrows #347's general metadata visibility into explicit C2 versus authored-view rules without redefining EncryptedField or the Message/Channel history policy.

For writes, current facts and the protected business mutation share the reviewed transaction/fencing discipline. Preserve the existing resolver's Organization → Member → Channel → current Membership/ACL lock hierarchy; within each multi-Actor/resource tier use a deterministic composite-key order. Add Task → Run → Approval/action → Grant/receipt guards consistently with every authority-changing writer. Session/Device, external policy, history and enrollment facts need transaction-valid versions/fences or locked authoritative rows; a timestamped cache is insufficient. The concrete adapter/storage task must prove this protocol before wiring commands. Fail/retry the whole transaction if a required version changes; never authorize first and commit later outside that scope. Stream/list emissions recheck current visibility per bounded page/batch; auth loss stops emission and reveals no further objects. No permission predicate is merely a SQL prefilter reused as authority.

## 5. Approval eligibility, scope and protected use

At RequestApproval, Core computes `snapshot = configured permitted Humans ∩ current parent readers ∩ allowed Task approval roles ∩ current policy/resource ceilings`. Roles are normally `APPROVER`. An `OWNER` enters this set only when server deployment is explicitly dedicated-dev/NOT PRODUCTION, owner self-approval is enabled, the creator is explicitly configured and OWNER is explicitly enabled for decide/revoke. Missing/false flags, production mode or a renderer claim cannot permit self-approval. This exception never changes Recovery's separate rules.

Snapshot Actor identities and policy/resource versions explain who was eligible; they are not permissions. For **approve, reject, revoke and every protected use**, intersect the stored snapshot with current eligible identities and the current authority over every requested resource. A new policy approver outside the snapshot cannot decide an old request. A changed role, Member/Device revocation, ACL deny, lost source/resource authority or disabled self-approval denies the next operation. An empty current intersection rejects RequestApproval without a pending record/Grant; a pending request with nobody eligible grants nothing. Unknown eligibility facts return unavailable, not “no approvers needed.” Restoring a role/policy cannot revive a revoked/expired Approval, blocked Run or safety barrier.

At protected use, resolve the recorded deciding Human's current Member/role/resource authority as facts; do not impersonate that Human or require a new interactive approval Session. Honor any still-required Session/Device binding and expiry of the actual delegation/Grant. Independently authenticate the executing Runtime and evaluate its current authority. A Runtime cannot call the Human decide/revoke route by presenting an approver ID; #365 uses the pure eligibility operation inside its own serialized admission interface. The set is valid only within that current fact/transaction scope and cannot be cached as permission.

Requested capabilities/scopes must fit current policy, initiating Human, assigned Agent delegation and resource ceilings; the request to obtain Approval does **not** require the not-yet-issued protected-action Grant. It still requires current Run execution authority. The issued grant satisfies `granted ⊆ requested ∩ initiator ∩ Agent delegation ∩ approver ∩ current resource policy`; no layer widens another. Empty `granted_capabilities` means exactly the requested set per existing Proto; an empty ResourceScope grants nothing and is never a wildcard. Unknown capabilities/scope fields are rejected. Only #348's configured synthetic `noop/1` action is executable here; real tools/files remain unsupported.

Decisions bind the exact action/decision revision and ONCE expiry from #347/#348. `approved=false` requires the same current decision eligibility as approval, issues no Grant and follows Core's durable denial/stop-intent transition. OBSERVER cannot reject Approval as a substitute for CancelRun. Revoke creates no new authority. Use additionally verifies the current authenticated execution owner/lease/fence, Grant signature/state/expiry and Core-issued Approval/Grant relation, immutable action binding, active Run, no cancel/barrier, current route/budget and still-current approver/initiator authority. At `now >= expiry`, deny immediately. #365 serializes consume/admit with cancellation/revocation; neither this decision, an approval notification nor an old signature permits offline effects.

## 6. Receipt reads and restricted reconciliation

`own_receipt_read` is available only after Core finds a committed operation binding matching the original tenant/Actor/Device/RPC namespace (Runtime adds Run/generation/owner binding). It is not a request flag that downgrades mutation checks. Check current parent visibility plus the corresponding current read action (`task.read`, `run.read` or `approval.read`) and receipt ownership; validate the original exact request identity before returning its result. No matching receipt means the full new-operation rules apply. Unknown purpose is invalid.

An authorized same-key duplicate may read immutable result identities plus the **current** authorized object view after the Run terminates, an Approval/Grant expires/revokes, or its former writer/approver loses mutation eligibility but retains read permission. It cannot return an old reusable Grant/allow, recreate a transition, restart work, consume again or extend expiry. Loss of membership, parent-read/Task-read policy or Device/Session authority denies the duplicate's disclosure. A full authored result still requires §4's source guard and #353; a metadata-only Run receipt cannot be used to retrieve those fields. Re-login on an authorized same Device can recover its own namespace with current authentication; another Actor/Device cannot read it. Same key with changed semantic fields conflicts only after current disclosure checks. #355 must clarify that a duplicate DecideApproval response returns the current Approval/issuance identity without reissuing reusable `capability_grant` bytes; its current optional wire field is not permission to replay an old credential.

Normal `run.report`/Runtime metadata reads fail when their ordinary authority is lost. #348's separately authenticated, exact original cleanup assignment may still accept verified stop/failure evidence and return minimized terminal receipts after execution lease/Grant expiry or Device revocation. That credential is not accepted by the ten ordinary action paths; it cannot read authored content, complete successful new execution, mint a replacement owner or clear an uncertain barrier by itself. Local supervisor stop remains available without Core; Core-confirmed cancellation still requires its durable proof/commit. Trusted Core automatic invalidation/revocation is a separate maintenance identity, not a Service/renderer bypass to Human approval.

## 7. Stable errors and reference evidence

| Refusal | Status / existing ErrorDetail code |
| --- | --- |
| Invalid/missing/expired Session or Runtime credential/audience | `UNAUTHENTICATED`; no object detail. |
| Missing/foreign object or mismatched caller-supplied child binding | `NOT_FOUND`; no foreign subject; applies to this Task profile, without changing existing Channel adapters. |
| Unknown action, unsupported actor route/mode/DM/editing/real tool | `UNIMPLEMENTED` for unsupported surface; a known action called by an ineligible principal is `PERMISSION_DENIED`. |
| Invalid shape/duplicate or unknown caller role/purpose | `INVALID_ARGUMENT`; no invented domain code. |
| Unavailable/incomplete/mismatched resolver facts, missing/uninterpretable policy/ACL version | `UNAVAILABLE`; no cached/default allow. |
| Inactive Organization/Member, role/policy/ACL/target/approver denial | `PERMISSION_DENIED / PERMISSION_DENIED`; Device revocation may use `DEVICE_REVOKED`. |
| No current Channel Membership; source history denied | `PERMISSION_DENIED / NOT_A_MEMBER` or `HISTORY_SHARING_DENIED`. |
| Retained source erased; Grant expired/revoked | `FAILED_PRECONDITION / RETENTION_EXPIRED`; `PERMISSION_DENIED / GRANT_EXPIRED` or `GRANT_REVOKED`. |
| Expanded capability/resource scope; missing required execution Grant | `PERMISSION_DENIED / GRANT_OUT_OF_SCOPE` or `APPROVAL_REQUIRED`; a missing Grant is never an implicit allow. |
| Wrong execution owner, lost lease or stale fence | `FAILED_PRECONDITION / NOT_EXECUTION_OWNER`, `LEASE_LOST` or `FENCING_TOKEN_STALE`. |
| Business terminal/cancel/barrier/expired Approval | `FAILED_PRECONDITION / INVALID_STATE_TRANSITION`; no revival. |
| Authorized same-key changed request; input limit | `ALREADY_EXISTS / IDEMPOTENCY_CONFLICT`; `RESOURCE_EXHAUSTED / PAYLOAD_TOO_LARGE`. |

Errors follow the [shared model](./error-model.md). Denied authorization creates no requested business write/Grant/effect; policy-required minimized denial audit or independently committed expiry reconciliation is separate and cannot claim command success. Content and raw action/Grant material never enter decision telemetry/audit/outbox. #356 owns action/event descriptor registration; this contract alone authorizes no registry or business write.
